# フレンド対戦・信頼できるゲームサーバー（試作）

## 実装内容

`server/src/index.ts` はサーバー実行専用のコードです。Firebase Admin SDKでIDトークンを検証し、ルームのホスト・ゲストだけを認可します。

- `GET /rooms/{code}/state` — 2人分の提出済み非公開デッキをサーバー側で検証し、初回のみシャッフル・初期手札配布。以後は保存済み状態を返す
- `POST /rooms/{code}/mulligan` — 本人のマリガンを確定。本文は `{"revision":0,"indices":[0,2]}`
- `GET /health` — ヘルスチェック

マリガンは**空・蛍がそれぞれ独立して操作**でき、先に完了した側は相手を待ちます。両者が確定してから空の先攻1ターン目（PP1）を開始します。自分のマリガンを再送しても手札を更新できないようにし、Firestoreトランザクションで同時確定時も安全に処理します。
`onlineMatches/{code}` に完全なゲーム状態を置きますが、**ブラウザのFirestore権限は拒否**されており、HTTPレスポンスにも相手の手札や山札の並びは含まれません。自分の山札の並びも公開しません。

**現在はマリガンと基本対戦操作のサーバー処理まで実装しました。**
`POST /rooms/{code}/action` の本文は `{"revision":2,"action":{"type":"endTurn"}}` の形式です。
受け付ける操作は、手札プレイ（`play`）、元素能力（`ability`）、フォロワー攻撃（`attackFollower`）、リーダー攻撃（`attackLeader`）、ターン終了（`endTurn`）の5種類です。
サーバー側でFirebase認証、ルームの参加者、現在の手番、ゲームフェーズ、リビジョン、操作形式を確認し、既存のゲームエンジンで計算します。

オンライン画面には**試験用操作パネル**を追加しました。特殊な複数対象指定や既存のアニメーション付きバトルUIとの統合は未完成です。サーバー配備前は利用できません。

## セキュリティと運用上の制約

- Cloud Firestoreクライアントから `onlineMatches` を読み書きできないルールは既存のcatch-all denyを維持しています
- `ALLOWED_ORIGIN` 以外のブラウザOriginは拒否します（CORSは認証の代用ではなく、Firebase IDトークンとルームのUIDを必ず検査します）
- Firebase Admin権限を持つサービスアカウント秘密鍵を**GitHub、Viteの環境変数、Webブラウザへ絶対に配置しないでください**
- サーバーのFirebase認証はGoogle Application Default Credentials（ADC）を使用します
- 対戦状態の保存先はFirestoreで、サーバー再起動後も試合が残ります。ルームを再利用しない運用です
- ルームとマッチの自動削除はまだありません。運用開始前にTTL／クリーンアップが必要です
- 既存対戦UIとの統合、特殊な複数対象指定、終了・降参、対戦ログ、カード効果の乱数と状態保存の厳密な監査は今後の課題です
- ゲームエンジンの乱数は現状 `Math.random` です。競技的な公平性が必要な段階でサーバー乱数源を強化します

## ローカルでサーバーを動かす場合（任意）

```bash
cd server
npm install
# Firebase Adminが利用できるADCを設定
# Windowsなら gcloud auth application-default login など
npm run check
npm run dev
```

`ALLOWED_ORIGIN` の既定値は `https://genshincard-25028.web.app`、`PORT` は `8080` です。

## 公開先サーバーが準備できた場合

`.env.local` に

```dotenv
VITE_MATCH_SERVER_URL=https://<信頼できる対戦サーバーのURL>
```

を追加して `npm run build` とHosting再デプロイを行います。
サーバーURLを設定していない間は、既存の「対戦セッション開始」表示のままです。安全でないクライアント対戦に切り替わることはありません。

**注意：Firebase Spark無料プランでこのNodeゲームサーバーが自動稼働するわけではありません。** 対戦サーバーを公開するには別のホスティング環境が必要です。Cloud Runなどを使う場合は課金アカウントや無料枠・予算上限を確認してから、利用者の承認を得てセットアップします。Firebase HostingだけではNodeサーバーは動きません。

## ユーザーが今できること

今のSparkプランを変えず、通常のゲームは従来どおり利用できます。今回追加したサーバーコードは配備していないため、オンライン初期手札画面はまだ利用できません。

## オンライン対戦画面の統合（段階1）

ローカル対戦のカード画像と盤面・手札・リーダー用CSSをオンライン画面で再利用し、クリック操作によるプレイ／攻撃／元素スキル・爆発／ターン終了を実装しました。ゲームロジックは引き続きサーバーだけで計算し、相手の手札の内容や山札の順番は送信しません。元素付着とシールドを表示します。

特定カードの対象指定・すべての演出、ドラッグ操作の完全互換などは追加検証・統合が必要です。新しい試合で確認してください。

## 対戦画面の完全共用（更新）

対戦開始後（双方のマリガン完了後）はフレンドロビーの埋め込みパネルを使用せず、ローカル対戦と同一の `src/App.tsx` バトル JSX / CSS をオンライン用に表示します。オンライン時だけサーバーから受け取った観戦可能情報に状態を投影し、手札クリック、攻撃、能力使用、ターン終了の操作を認証付きオンラインコマンドに変換します。相手の手札のID、山札の内容・順番はクライアントへ渡しません。オンラインモードではカード一覧とロビー退出が利用できます。

オンライン操作の演出トレースはローカルと同一の再生方式にはまだ統合されていません。状態表示と画面レイアウトは共用しますが、演出や通信の挙動は別途動作検証が必要です。

## オンライン演出同期

サーバーが各対戦操作を `beginPresentation` → ゲーム処理 → `captureFrame` → `compactPresentationFrames` で記録します。最新5操作について、開始前の盤面と最大12枚の変化フレームを保持します（Firestoreのドキュメント肥大化を防ぐための上限）。

各レスポンスでは最新の対戦状態に加え、閲覧者ごとに投影した演出履歴を返します。相手の手札カードIDや双方のデッキ順序は演出フレームでも返しません。ブラウザはrevision順に受信した行動をキューへ入れ、既存のローカル演出UIの再生速度変更・スキップ機能で表示します。対戦画面の折りたたみ「対戦行動履歴」には、カードの使用、攻撃、元素スキル・爆発、ターン終了の直近操作名を表示します。

ポーリング間隔は従来どおり2.5秒です。5操作より多く進んでから観戦クライアントが復帰した場合や、通信不能だった期間については、保持上限より古い演出までは再生できません。高速のリアルタイム演出ではなく、サーバー確認済みの順次再生です。
