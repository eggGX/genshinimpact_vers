# カードデータの追加方法

STEP 22 で、カードデータをゲームエンジンから分離しました。

- `testCards.ts`: ゲームの動作確認用カード
- `productionCards.ts`: 正式カードの登録先（現時点では空）
- `cardRegistry.ts`: 全カードのID検索、重複チェック、デッキ候補の抽出

## 正式カードを追加する

`productionCards.ts` に `Card` 型のデータを追加してください。追加後は `getCard(id)` で自動的に検索でき、通常カードは `getDeckCardPool()` の候補になります。ゲームエンジンの条件分岐を追加する必要はありません。

今後、各元素を別ファイルへ分割する場合も、`productionCards.ts` で配列を統合するだけです。

## ルール上の注意

- `id` は全カード（テストカード・トークンを含む）で一意にします。重複したIDや空IDは起動時に例外になります。
- `token: true` のカードは `getCard` で参照できますが、デッキ候補には入りません。
- 元素スキルは `elementalSkill`、元素爆発は `elementalBurst` で定義します。効果は `CardEffect` の配列です。
- `elementalCreature: true` のカードは固有元素の付着を維持します。
- カードのゲーム上の処理が現在の `CardEffect` で表現できない場合だけ、共通効果の種類を拡張します。

正式115枚の内容は今回まだ登録していません。各カードの効果が確定した段階で元素ごとに登録していきます。
